# Phase 5: Registry, Showcase and Preview

Status: Draft v1 (2026-10-13)
Depends on: P4 (registry and preview), P8.T1 (sandbox regeneration)
Blocks: P9
Areas: `registry/`, `apps/sandbox`, `apps/preview`, `tools/generate_checksums.dart`

## 1. Summary

Make every Flutter surface outside the library show Ink and Paper: the
registry users download, the CLI sandbox (`apps/sandbox`) and the Widgetbook
workbench (`apps/preview`). Nothing here is hand-edited except the preview use
cases.

## 2. Background

1. `registry/` mirrors `packages/core/lib/src/components` and is generated by
   `tools/generate_checksums.dart`. Per-preset folders were removed in commit
   `38af1d7`; `files_for_preset` falls back to `default`.
2. `registry/index.json.sig` is produced by the hidden CLI command
   `justui sign-registry` (`packages/cli/src/main.rs:277`).
3. `apps/sandbox/lib/{core,tokens,widgets}` are generated by the CLI. Its
   current theme uses `fromSeed(0xFF3B82F6)` with the neobrutalism preset.
   Since 2026-10-24 the sandbox lives in `apps/sandbox`; `apps/showcase` is
   the Flutter Wasm bridge that renders core components on the docs pages
   (`.agents/rules/flutter.md`, "apps/showcase (bridge)") and is not
   regenerated by this phase.
4. `apps/preview/lib/usecases/` has 30 files. `tokens_usecases.dart` shows
   swatches built on the old schemes and iOS-style literals (`#007AFF`,
   `#FF3B30`, `#666666`, `#111111`).

## 3. Goals

1. Registry in sync with core and signed.
2. Sandbox regenerated through the CLI with the new init template.
3. Widgetbook shows every component in 4 combinations and a live role table.
4. A guard that prevents identical per-preset registry folders from returning.

## 4. Non-goals

1. Changing the registry format or the signing scheme (see `91-out-of-scope.md`).
2. Redesigning the sandbox gallery layout.

## 5. Functional requirements

### FR-5.1 Registry sync

1. Run `dart run tools/generate_checksums.dart --dry-run`, read the drift
   report (it can report drift and still exit 0), then run it without
   `--dry-run`.
2. Re-sign with `cargo run -p justui -- sign-registry`.
3. Every entry keeps `supportedPresets: ["default", "neobrutalism"]`.
4. No `neobrutalism` file key is added to any entry.

### FR-5.2 Identical-preset guard

Extend `tools/generate_checksums.dart` so that, if a component ever has a
preset-specific file whose bytes equal its `default` file, the run fails with a
message naming the file. A preset folder is allowed only when its bytes differ.

### FR-5.3 Sandbox regeneration

Follow the recipe in `.agents/rules/flutter.md` (section "apps/sandbox (generated)"):

```
cargo build --release
cd apps/sandbox
rm -rf lib/core lib/tokens lib/widgets
../../target/release/justui init -y --preset neobrutalism --color-space oklch --dart-target standard
sed -i 's#^registry_url:.*#registry_url: ../../registry#' justui.config.yaml
../../target/release/justui add --all -y
dart format lib && flutter analyze && flutter test
```

Requirements:

1. Run only after P8.T1, so `init` writes `JustThemeData.inkAndPaper`.
2. `apps/sandbox/lib/main.dart` changes only if the gallery calls an API that
   is now deprecated.
3. The gallery must offer a light and dark toggle and a preset toggle if it
   does not already.

### FR-5.4 Preview tokens use case

Rewrite `apps/preview/lib/usecases/tokens_usecases.dart`:

1. A role table per mode and preset: role name, swatch, hex, and the measured
   ratio against canvas computed at runtime with `contrastRatioWith`.
2. A tint knob (hue 0 to 359, chroma 0 to 0.010) that rebuilds the theme with
   `JustThemeData.inkAndPaper(tint: ...)` and shows the minimum ratio.
3. Remove every literal color.

### FR-5.5 Preview coverage

Each of the 29 component use-case files covers default and neobrutalism, light
and dark, and the error, disabled, focused and selected states that the
component supports.

## 8. Acceptance criteria

1. AC-5.1: Dry run shows no drift after writing; the signature verifies through
   a local-registry `justui add` in the sandbox regeneration.
2. AC-5.2: A test copy with an identical preset folder makes the checksum tool
   fail.
3. AC-5.3: In `apps/sandbox`, `dart format lib`, `flutter analyze` (no
   `unnecessary_import` infos) and `flutter test` pass (owner machine).
4. AC-5.4: `apps/sandbox/lib/core/theme/just_theme.dart` contains
   `inkAndPaper` and no `fromSeed`.
5. AC-5.5: `dart run build_runner build --delete-conflicting-outputs` runs in
   `apps/preview` and Widgetbook shows no runtime errors in 4 combinations
   (owner machine).
6. AC-5.6: `flutter analyze` passes in `apps/preview`; no color literal remains
   in `tokens_usecases.dart`.
