Kritis

Kode yang diterima user tidak bisa dikompilasi, atau CI dipastikan merah.

#01

CLI menulis import yang tidak bisa di-resolve untuk hampir semua komponen

Kritis

Sejak commit 7f7bbee ("explicit typings"), komponen core meng-import path internal seperti package:just_ui_core/src/theme/preset_tokens.dart. Rewriter import hanya mengambil nama file terakhir, sementara file core diekstrak dengan subfolder tetap ada.

Bukti: import_rewriter.rs:289-294 mengambil segmen terakhir, embedded_templates.rs:75-79 menyimpan ke lib/core/theme/…. Output rewrite() asli pada file registry:

import 'package:my_app/core/preset_tokens.dart';  // file sebenarnya: core/theme/preset_tokens.dart
import 'package:my_app/core/theme_data.dart';     // file sebenarnya: core/theme/theme_data.dart

Dampak: select, toast, radio, button, input, card, dan sekitar 20 komponen lain gagal dikompilasi setelah justui add. apps/showcase tidak terdampak hanya karena di-generate sebelum commit tersebut.

#02

dart_target: standard (nilai default) tidak berfungsi

Kritis

117 dari 165 file registry sudah ditulis dengan sintaks primary constructor eksperimental, contohnya class const JustThemeProvider({…}) extends StatefulWidget. CLI hanya punya transpiler satu arah, dari standard ke primary.

Bukti: constructor_transpiler.rs:239 hanya berisi transpile_to_primary_constructor. Default Standard ada di config.rs:50 dan fallback di env_resolver.rs. Root repo sendiri harus menyalakan enable-experiment: primary-constructors di analysis_options.yaml.

Dampak: user dengan SDK yang belum mendukung fitur ini tetap menerima kode primary constructor, termasuk file core hasil ekstraksi init.

#05

justui upgrade mengganti binary tanpa verifikasi checksum

Kritis

execute_upgrade hanya mengunduh, membongkar, lalu menimpa executable yang sedang berjalan. install.sh justru memverifikasi SHA256SUMS dan batal kalau hash tidak cocok.

Bukti: upgrade.rs:303-310: download_and_unpack langsung diikuti replace_current_executable. Satu-satunya penyebutan checksum di file itu adalah untuk melewati aset .sha256.

Dampak: jalur upgrade lebih lemah daripada jalur install pertama.

Bug logika dan performa

Perilaku runtime yang tidak sesuai klaim atau pedoman proyek.

#06

Tema dihitung ulang setiap kali diakses; cache ThemeData hampir tidak pernah kena

Tinggi
  • Getter JustThemeProviderState.theme menjalankan applyHighContrastOverrides(), spacing.resolve(), radius.resolve(), animations.resolve(), lalu copyWith() setiap kali dipanggil (theme_provider.dart:88-122).
  • context.justColors, justTypo, dan sejenisnya selalu lewat getter ini. JustButton.build memanggilnya 4× per build (just_button.dart:232, 262-273).
  • toThemeData() memakai Expando berbasis identitas objek (theme_data_material.dart:5,12). Karena provider selalu membuat instance baru, cache hanya kena untuk instance static seperti JustThemeData.light.
  • Getter shadow membuat List<BoxShadow> baru setiap diakses (shadow_scheme.dart:139+).

Dampak: bertentangan dengan klaim "lazy-cached" dan "zero heap allocation" di AGENTS.md.

#07

Pedoman aspect-based rebuild dilanggar oleh kode sendiri

Tinggi

Ada 50 pemanggilan JustThemeProvider.of(context) tanpa aspek, artinya widget berlangganan ke semua aspek tema. Terbanyak di sidebar (5), input (4), dan breadcrumb (4).

Bukti: di just_button.dart:230-232 komentarnya menyebut "resolves InheritedModel aspects properly", tapi baris di bawahnya subscribe ke semua aspek. Pemanggilan per-aspek setelahnya jadi tidak berpengaruh.

#08

Theme extension komponen tidak pernah didaftarkan di core

Tinggi

theme_data_material.dart:21-23 berisi extensions: const [ // CLI:REGISTER_EXTENSIONS ], yaitu list kosong. Padahal 27 file komponen membaca Theme.of(context).extension<JustXTheme>().

Dampak: di package core dan app preview, semua extension ini selalu null. Kustomisasi tema per komponen tidak bisa diuji di dalam monorepo.

#09

Default haptic tidak konsisten dan fallback preset tidak pernah tercapai

Tinggi
  • JustButton memakai presetTokens.showsDefaultBorder sebagai default haptic, yaitu flag untuk border. Checkbox dan switch memakai selectionHapticDefault.
  • Field enableHaptic di JustButtonTheme bertipe non-nullable dengan default false. Begitu theme didaftarkan, ekspresi buttonTheme?.enableHaptic ?? preset… tidak pernah jatuh ke nilai preset.
#10

Error CLI keluar dengan exit code 0

Tinggi

Pola logger::error(...); return Ok(()) dipakai di banyak tempat, contohnya add.rs:58-64, 74, 102. Ada 44 logger::error di folder commands/.

Dampak: "Project not initialized" atau registry gagal di-fetch tetap exit 0. CI dan skrip user tidak bisa mendeteksi kegagalan.

#11

Flag global --quiet, --no-color, --json tidak pernah dibaca

Tinggi

Ketiganya dideklarasikan di main.rs:27-44 dan muncul di --help. Dispatch di main.rs:267+ tidak pernah membaca cli.quiet, cli.no_color, atau cli.json. --json hanya berfungsi di list, lewat argumen lokal milik list sendiri.

#12

Klaim integritas SHA-256 lebih kuat dari kenyataannya

Tinggi

Checksum diambil dari index.json yang di-fetch dari sumber yang sama, yaitu branch main tanpa pin versi (config.rs:21). Ini hanya melindungi dari korupsi saat transfer, bukan dari file yang diubah di sumbernya. Tidak ada signing.

Dampak: CLI v0.14 selalu mengambil registry main terbaru, jadi versi CLI dan registry bisa tidak cocok tanpa peringatan.

#13

Neobrutalism: translasi saat ditekan tidak selalu sama dengan offset bayangan

Tinggi
  • Offset shadow bervariasi dari 2 sampai 12px per level elevasi (shadow_scheme.dart:142-182).
  • Translasi saat ditekan di-hardcode Offset(4.0, 4.0) (preset_tokens.dart:320, theme_data.dart:67). Komponen dengan shadow xs (2px) bergeser 4px, jadi klaim Prest = Ppressed tidak berlaku untuk semua level.
  • Simulator di docs memakai border-2 (2px) dan shadow campuran 2.5px/3px, sementara Flutter memakai border 2.5 dan offset 4.

Build, CI, dan release

Pipeline yang rapuh, tidak reproducible, atau tidak mengecek hal penting.

#21

Konfigurasi Melos kemungkinan besar sudah tidak terpakai

Sedang

Root memakai melos: ^8.7.0 dengan melos.yaml. Menurut changelog Melos 7, konfigurasi pindah ke pubspec.yaml dan wajib memakai pub workspace. Root pubspec.yaml tidak punya workspace:, package tidak punya resolution: workspace, dan usePubspecOverrides sudah tidak dipakai lagi.

Catatan: belum diverifikasi dengan menjalankan melos bootstrap, karena SDK Dart tidak tersedia di sandbox.

#22

Pipeline changesets rapuh

Sedang
  • .changeset/config.json memakai key packages dengan tipe dart/rust. Itu bukan skema Changesets, yang hanya melihat workspace npm (apps/docs).
  • Nama justui_cli di changeset tidak sama dengan nama crate justui.
  • release.yaml menjalankan bun changeset version setelah skrip bump manual, lalu push langsung ke main. Tidak ada tag yang dibuat otomatis.
#23

Cache Cargo di CI menyimpan folder yang salah

Sedang

Workspace Cargo ada di root, jadi hasil build masuk ke ./target. Cache di ci.yaml:115, 149, 203, 235, 268 menyimpan packages/cli/target, sehingga setiap job membangun ulang dari nol.

#24

Sisa debugging dan versi tool yang tidak dipin

Sedang
  • Langkah "Debug — find binary" masih ada di release.yaml:121.
  • bun-version: latest (ci.yaml:62, release.yaml:30) dan Flutter stable tanpa pin.
  • .fvmrc berisi "stable", sementara melos.yaml bergantung pada symlink .fvm/flutter_sdk.
#25

Pengecekan registry dan end-to-end tidak ada di CI

Sedang

  • Tidak ada validasi registryDependencies terhadap import (akan menangkap #03).
  • registry/** di-exclude dari analyzer (analysis_options.yaml).
  • Tidak ada tes justui init && add --all && flutter analyze pada proyek baru. Satu tes ini akan menangkap #01 sampai #03 sekaligus.

Urutan perbaikan yang disarankan

Diurutkan dari yang paling cepat memulihkan CI dan membuka blokir user.

  1. Bersihkan baris duplikat di navbar.test.tsx supaya CI docs hijau lagi. #04
  2. Tambahkan tes E2E di CI: justui init dan add --all pada proyek Flutter baru, lalu flutter analyze. #01 #02 #03 #25
  3. Generate registryDependencies langsung dari import, misalnya sebagai bagian dari generate_checksums.dart. #03 #20
  4. Pilih satu sintaks sebagai source of truth. Paling aman: source ditulis dengan constructor standar, lalu CLI men-transpile ke primary constructor sebagai opsi. #02
  5. Verifikasi SHA256SUMS di justui upgrade, dan kembalikan exit code non-zero untuk semua error CLI. #05 #10
  6. Hitung tema sekali di build() provider dan simpan hasilnya di _JustThemeModel, bukan di getter yang dihitung ulang. #06 #07
  7. Sinkronkan README, AGENTS.md, CONTRIBUTING.md, dan docs dengan kode. Bagian yang bisa di-generate dari index.json sebaiknya di-generate. #14 – #19
Metode: kode dibaca manual; skrip Python membandingkan import vs index.json dan checksum registry; cargo test, clippy, eslint, tsc, dan vitest dijalankan di salinan scratch. Tes Flutter/Dart tidak dijalankan karena SDK tidak tersedia, sehingga #21 masih perlu dikonfirmasi dengan melos bootstrap.
