The JustUI color system is designed with a primary focus on visual beauty, high performance, and full compliance with **WCAG 2.0 (AA)** web accessibility standards. Color tokens are separated between raw primitive palettes and functional semantic mappings that adapt dynamically based on the active theme and selected preset.

## 2. Semantic Color Scheme (`JustColorScheme`)

JustUI maps primitive palettes into functional semantic color schemes through the `JustColorScheme` class. This mapping ensures UI components use consistent color tokens across all states.

### Key Properties of `JustColorScheme`

The color scheme defines several color categories as follows:

- **Surface Colors**: `background` (page background), `card` (card container), `elevated` (floating dialog/overlay), `overlay` (transparent modal background).
- **Text Colors**: `textPrimary` (high contrast/headings), `textSecondary` (descriptions/body text), `textDisabled` (inactive text), `textInverse` (text on high-contrast backgrounds).
- **Border Colors**: `borderDefault` (input dividers/subtle lines), `borderFocus` (active focus indicator border), `borderError` (error state border).
- **State Colors**: `success` (success/safe), `warning` (warning/attention), `error` (error/danger), `info` (information/guidance).

### Light Mode vs Dark Mode (Default)

By default (`JustThemePreset.default_`), JustUI defines the semantic color scheme as follows:

## 3. Neobrutalism Visual Preset

JustUI supports the **Neobrutalism** design style (`JustThemePreset.neobrutalism`). This preset forces the color scheme to use extremely high contrast with thick black/white borders, without gradients or soft color transitions.

- **Neobrutalism Light Mode**: Uses a warm cream background (`Color(0xFFFFFDF5)`), solid black primary text (`Color(0xFF000000)`), and forces border colors (`borderDefault`, `borderFocus`, `borderError`) to solid black in every state.
- **Neobrutalism Dark Mode**: Uses a deep dark gray background (`Color(0xFF121212)`), solid white primary text (`Color(0xFFFFFFFF)`), and forces all borders to solid white.

## 4. Color Contrast Accessibility Audit (WCAG AA)

Interface readability is a top priority. JustUI includes a built-in contrast accessibility audit system through the `JustColorAccessibility` extension on the `Color` class.

### Contrast Ratio Formula

Relative luminance (L) is calculated based on the standard RGB color curve (obtained via Flutter's internal `Color.computeLuminance()` method), producing a value between `0.0` (solid black) and `1.0` (solid white).

The WCAG 2.0 contrast ratio formula is:

```text
R = (L1 + 0.05) / (L2 + 0.05)
```

Where L1 is the luminance of the lighter color, and L2 is the luminance of the darker color. The constant `0.05` is added to compensate for human eye adaptation to screen glare.

### `JustColorAccessibility` Extension Methods

This extension provides two main APIs:

1. `contrastRatioWith(Color other)`: Produces a ratio value between `1.0` (no contrast/same color) and `21.0` (perfect black and white contrast).
2. `isAccessibleWith(Color other, {bool isLargeText = false})`: Checks contrast compliance against WCAG AA standards:
   - **Normal Text**: Requires a minimum contrast ratio of **4.5:1** against the background.
   - **Large Text / Visual Components** (such as input borders, focus indicators, or badges): Requires a minimum contrast ratio of **3.0:1**. Large text is defined as text sized ≥ 18pt/24px (or bold text ≥ 14pt/18.67px).

```dart
// Example of manual contrast audit usage:
final Color background = context.justColors.background;
final Color textColor = context.justColors.textSecondary;

final double ratio = textColor.contrastRatioWith(background);
final bool isAccessible = textColor.isAccessibleWith(background);

print('Contrast Ratio: $ratio (Passes WCAG AA: $isAccessible)');
```

## 5. Dynamic Contrast Enforcement (`JustThemeData.fromSeed`)

When initializing a custom theme using the `JustThemeData.fromSeed(Color seedColor)` generator method, JustUI runs an automatic algorithm at runtime to ensure the resulting brand/primary colors still meet accessibility contrast against the background color.

### Lightness Adjustment Algorithm (`colors_dynamic.dart`)

If the original primary color does not meet the minimum contrast ratio against the background:

1. **Brightness Direction Detection**: The system evaluates the brightness level of the background (`bgLuminance < 0.5`). If the background is dark, the primary color must be adjusted lighter. If the background is light, the primary color is adjusted darker.
2. **Binary Search (8 Iterations)**: Uses a binary search algorithm on the Lightness parameter of the source color's HSL scale. This algorithm finds the nearest lightness value that meets the target contrast ratio while preserving the Hue and Saturation values to maintain brand color aesthetics.
3. **Preset Bypass**: This dynamic HSL compensation algorithm is automatically bypassed when the active visual preset is `neobrutalism`, in order to preserve the characteristic thick black border aesthetics of neobrutalism.

## 6. Best Practice Example for Consuming Colors in Flutter

To keep widget tree rendering performance optimal during color transitions (such as dark mode toggle), ensure you consume colors using the correct context aspect.

```dart
class CustomCardWidget extends StatelessWidget {
  const CustomCardWidget({super.key});

  @override
  Widget build(BuildContext context) {
    // Registering widget ONLY on the color aspect.
    // Widget will not rebuild if other aspects (such as spacing/typography) change.
    final colors = context.justColors;

    return Container(
      padding: .all(16.0),
      decoration: BoxDecoration(
        color: colors.card,
        border: Border.all(color: colors.borderDefault),
        borderRadius: const BorderRadius.all(Radius.circular(8.0)),
      ),
      child: Text(
        'Visual Primitive Audit',
        style: TextStyle(color: colors.textPrimary),
      ),
    );
  }
}
```
