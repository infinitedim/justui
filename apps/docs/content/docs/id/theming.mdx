# Sistem Tematik & Kustomisasi

JustUI dirancang dengan fokus utama pada performa tinggi dan minimalisasi beban render ulang (_rebuild overhead_). Dokumen ini membahas secara mendalam arsitektur mesin tema (theming engine) JustUI, bagaimana Aspect-Based Rebuilds bekerja, sistem lazy caching menggunakan `Expando`, serta pedoman praktis untuk konsumsi tema secara efisien.

---

## 1. Konsep Core Theming Engine

Inti dari kustomisasi visual JustUI dikelola oleh kelas `JustThemeData`. Kelas ini merangkum seluruh visual primitive tokens menjadi satu konfigurasi terpadu:

- **Colors (`JustColorScheme`)**: Kumpulan warna semantik dan warna permukaan (background, card, textPrimary, borderFocus, dll.).
- **Typography (`JustTypographyScheme`)**: Skala tipografi modern berbasis font Inter (atau JetBrains Mono untuk monospace) serta dukungan fluid typography.
- **Spacing (`JustSpacingScheme`)**: Jarak margin dan padding berbasis kelipatan 4px.
- **Radius (`JustRadiusScheme`)**: Kelengkungan sudut untuk komponen dan kontainer.
- **Shadows (`JustShadowScheme`)**: Kedalaman bayangan multi-layer.
- **Animations (`JustMotionProfile`)**: Durasi dan kurva pelandaian animasi (standard, expressive, compact, dan reduced).
- **Preset (`JustThemePreset`)**: Penentu gaya visual utama (default modern vs neobrutalism).

Sistem menyebarkan konfigurasi ini ke seluruh pohon widget menggunakan `JustThemeProvider`.

## 2. Aspect-Based Rebuilds (`InheritedModel`)

Pada Flutter, `InheritedWidget` tradisional akan memaksa _seluruh_ widget anak yang mengonsumsi data tema untuk me-rebuild dirinya kapan pun ada perubahan sekecil apa pun pada tema.

Untuk mengatasinya, JustUI mengimplementasikan **Aspect-Based Rebuilds** menggunakan `InheritedModel<JustThemeAspect>`.

### Daftar Aspek (`JustThemeAspect`)

Setiap aspek didefinisikan dalam enum `JustThemeAspect`:

```dart
enum JustThemeAspect {
  colors,      // Hanya mendengarkan perubahan warna
  typography,  // Hanya mendengarkan perubahan font/gaya teks
  spacing,     // Hanya mendengarkan perubahan jarak/spacing
  radius,      // Hanya mendengarkan kelengkungan sudut
  shadows,     // Hanya mendengarkan bayangan
  animations,  // Hanya mendengarkan profil gerakan/durasi animasi
  preset,      // Mendengarkan pergantian preset visual
}
```

### Cara Kerja Evaluasi Rebuild

Di dalam model internal `_JustThemeModel`, metode `updateShouldNotifyDependent` melakukan perbandingan aspek secara spesifik:

```dart
@override
bool updateShouldNotifyDependent(
  _JustThemeModel oldWidget,
  Set<JustThemeAspect> dependencies,
) {
  if (dependencies.contains(JustThemeAspect.colors) &&
      themeData.colors != oldWidget.themeData.colors) {
    return true;
  }
  if (dependencies.contains(JustThemeAspect.typography) &&
      themeData.typography != oldWidget.themeData.typography) {
    return true;
  }
  if (dependencies.contains(JustThemeAspect.spacing) &&
      themeData.spacing != oldWidget.themeData.spacing) {
    return true;
  }
  if (dependencies.contains(JustThemeAspect.radius) &&
      themeData.radius != oldWidget.themeData.radius) {
    return true;
  }
  if (dependencies.contains(JustThemeAspect.shadows) &&
      themeData.shadows != oldWidget.themeData.shadows) {
    return true;
  }
  if (dependencies.contains(JustThemeAspect.animations) &&
      themeData.animations != oldWidget.themeData.animations) {
    return true;
  }
  if (dependencies.contains(JustThemeAspect.preset) &&
      themeData.preset != oldWidget.themeData.preset) {
    return true;
  }
  return false;
}
```

**Skenario Dunia Nyata**: Jika pengguna mengganti mode tema dari terang ke gelap (mengubah `colors`), widget yang hanya mengonsumsi spacing (`context.justSpacing`) **tidak akan di-rebuild**. Hanya widget yang mendaftarkan dependensi pada warna (`context.justColors`) yang akan di-rebuild. Hal ini menghemat siklus CPU rendering secara signifikan, terutama pada widget tree yang kompleks.

## 3. Lazy Caching Material `ThemeData` via `Expando`

Meskipun komponen JustUI dibuat tanpa ketergantungan langsung pada widget Material bawaan Flutter, JustUI menyediakan jembatan integrasi menggunakan metode ekstensi `.toThemeData()` pada `JustThemeData`.

Menghitung ulang geometri, warna, dan dekorasi untuk menghasilkan Material `ThemeData` di setiap siklus render adalah proses yang memakan biaya komputasi. Oleh karena itu, JustUI menggunakan teknik lazy caching berbasis **weak references** melalui kelas `Expando`:

```dart
final Expando<ThemeData> _themeDataCache = Expando<ThemeData>();

extension JustThemeDataMaterialExtension on JustThemeData {
  ThemeData toThemeData() {
    return _themeDataCache[this] ??= _buildMaterialTheme();
  }
}
```

### Mengapa menggunakan `Expando`?

1. **Lazy Evaluation**: Objek `ThemeData` tidak akan pernah dibuat sebelum `.toThemeData()` dipanggil pertama kali.
2. **Mencegah Memory Leak (Kebocoran Memori)**: `Expando` menggunakan referensi lemah (_weak reference_) untuk memetakan instans `ThemeData` ke `JustThemeData`. Jika instans `JustThemeData` dihapus oleh _garbage collector_, data cache di dalam `Expando` akan ikut terhapus secara otomatis dari memori.

## 4. Panduan Konsumsi Tema: Build vs Callback

Untuk menjaga performa aplikasi tetap optimal, Anda harus mengikuti aturan tegas mengenai cara mengonsumsi tema dari context.

### Di Dalam Metode `build` (Rebuild Terdaftar)

Saat merender UI, Anda wajib menggunakan getter ekstensi aspek spesifik. Ini mendaftarkan widget sebagai pendengar (_listener_) pada aspek tertentu saja:

```dart
@override
Widget build(BuildContext context) {
  // ✅ REKOMENDASI: Hanya me-rebuild widget jika warna berubah
  final colors = context.justColors;

  // ✅ REKOMENDASI: Hanya me-rebuild widget jika spacing berubah
  final spacing = context.justSpacing;

  return Container(
    color: colors.background,
    padding: .all(spacing.md),
    child: const Text('JustUI'),
  );
}
```

- **Hindari** penggunaan `context.justTheme` pada widget kecil/daun (_leaf widget_), karena `justTheme` akan meregistrasikan listener ke _seluruh_ aspek tema. Akibatnya, widget tersebut akan dibangun ulang saat aspek apa pun (seperti spacing atau radius) berubah.

### Di Dalam Callback & Handler (Bebas Rebuild)

Pada callback interaktif (seperti `onPressed`, `onTap`) atau metode siklus hidup (seperti `initState`), Anda tidak memerlukan pendaftaran listener. Menggunakan listener di sini hanya akan memicu render ulang yang sia-sia.

Gunakan metode `context.readTheme()` untuk mengambil nilai tema secara instan tanpa mendaftarkan ketergantungan rebuild:

```dart
JustButton(
  label: 'Simpan',
  onPressed: () {
    // ✅ REKOMENDASI: Mengakses tema tanpa mendaftarkan widget untuk rebuild
    final activeTheme = context.readTheme();

    if (activeTheme.preset == JustThemePreset.neobrutalism) {
      // Panggil aksi haptic atau logika spesifik lainnya
    }

    saveData();
  },
)
```

Dengan memisahkan konsumsi bertipe **reactive** di metode `build` dan **imperative** di dalam callback, performa render aplikasi Flutter Anda akan tetap stabil pada 60fps/120fps.
